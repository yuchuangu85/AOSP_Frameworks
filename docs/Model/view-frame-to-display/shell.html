从 App VSync 到屏幕呈现

应用把 View 树的变化画进窗口缓冲；SurfaceFlinger（SF）在自己的帧回调里选择可用的图层内容，再交给显示硬件。两条链在缓冲和事务处汇合，不是一次从 App 直调到屏幕的调用。

两种 VSync逐阶段流程典型对照影响因素索引真机如何定位源码与边界

树深 ≠ 每帧全树重画

先数受约束或失效的子树，再数实际重测、重录和 GPU 覆盖的区域。

图片多 ≠ 每帧重新解码

区分首次加载、纹理是否驻留、实际绘制次数，以及最后覆盖多少像素。

同帧动画 ≠ 多线程并行

相同帧时刻可以推进多个动画。决定压力的是谁更新、更新什么、失效范围有多大。

01 / CLOCKS

“收到 VSync”有两个不同的执行点

上游时基：HWC 报告硬件 VSYNC 样本；SF 用有效样本校准显示节奏，而不是在硬件回调内画图。调度器用预测目标减去就绪与工作提前量安排唤醒。EventThread 收到回调后构造含目标和就绪时间的事件，再给订阅的应用连接分发。App 收到的事件时间戳不是物理面板此刻显示了新内容。

两个接收者：App 的接收器把事件投给 UI Looper；SF 自己注册的 sf 回调则把 frame signal 投给 SF 主 Looper。事务会请求或合并调度，但一条事务、一个 App VSync、一次 SF 唤醒、一次显示刷新并非一一对应。本文的“SF 收到 VSync”指后者，不指测试注入。

预算不是周期：固定 60 / 90 / 120 Hz 的理想刷新周期由 1000 ÷ Hz 得到，约为 16.67 / 11.11 / 8.33 ms；这不是 App 独占的 UI 时间，也不是本页实测。要看被选中的 FrameTimeline 的 deadline 与 expected presentation time、实际唤醒、流水线重叠及是否错过采纳机会。

05 / FIELD GUIDE

找到最先错过目标的那一段

  1. 先锁定是哪一帧、哪一个窗口。 在真机 Perfetto 采集可用的 FrameTimeline、gfx/view、sched、Binder 及设备支持的 GPU/fence 数据。选现象对应的窗口 SurfaceFrame，结合进程、layer 名、时间及 token 关联 DisplayFrame；不要用“时间上离得最近”代替关联。App token 与 display frame token 不是必须相等的同一个编号。@@TRACEID@@
  2. 判断是没被调度到，还是被工作占满。 查 UI 线程上 Choreographer#doFrame 的实际开始，分解 input、animation、traversal、measure、layout、draw。与线程 runnable/running/阻塞状态对齐；若自定义回调内部混有绑定或解码，添加应用 trace 标记，而不是按 slice 名称猜。@@TRACEUI@@
  3. 沿同一缓冲看交接和等待。 找 RT 的 DrawFrames、sync、资源准备、issue/swap、queue，再看 GPU 完成、acquire 依赖、BLAST 的 frameNumber。queue 早而 GPU 晚、RT 等空槽、UI 等 RT 是三种不同机制。FrameMetrics 的 DRAW 是录制区间、GPU_DURATION 是特定时间戳之差；TOTAL 不是各项相加，也不是 input-to-photon。@@TRACERT@@
  4. 最后检查 SF 所作的选择。 看 SF 的 frame signal / commit、该层的事务与 latch、合成类型以及 present fence。区分 pending、dropped、已提交和已呈现。FrameTimeline 将未完成的 present fence 留待处理；trace 缺轨道或 fence 无效时，结论应是“无法判定”，不是耗时为零。@@TRACESF@@
  5. 用对照求本机上限，而非寻找通用 N。 固定设备、分辨率、实际刷新模式、素材尺寸与可见面积、动画轨迹、缓存冷热和温度；分别测试同属性的 1、8、24、48 个可见对象（示例梯度，可自定）。分别对照“各子项平移 / 移动共同父项 / 改宽高 / 重绘内容”。记录实际活跃属性数、每帧调用次数、各阶段耗时分布、相对 deadline 的余量和晚呈现占比；多次重复、分开首帧与稳态。若 GPU、后台抢占、降频或窗口策略同时变化，不把差值全算在 View 数量上。
06 / PROVENANCE

源码、证据强度与范围

直接证据：仓库 README 标注 android17-release；本页引用固定在本地快照 @@COMMIT@@。路径相对本仓库，并非声称与某个未核实的上游 tag 完全一致。下列行均嵌入页面，离线也可查看。

推论：“影响因素”和对照描述的是某一条件如何增加工作或依赖，不是每帧都执行的保证。无前序事件、无有效 Surface、绘制取消、空 damage 或无新事务等分支可以跳过大段工作。

未知：本文主线是普通硬件加速 View 窗口与物理显示；软件绘制、独立 Surface、RT-only 和多输出在差异处说明。不是对游戏引擎、Compose 重组、网页内部排版、显示驱动或面板扫描电路的实现追踪。厂商 overlay 能力、DVFS、热限频、内存带宽、调度抢占及外部生产者负载须实测。显示 fence 不是逐像素光学证据；端到端发光需设备侧测量。
