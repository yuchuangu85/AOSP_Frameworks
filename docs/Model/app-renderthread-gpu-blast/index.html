ANDROID 17 · SOURCE-BACKED RENDER PIPELINE

APP 绘制完成后，如何交给 RenderThread / GPU / BLAST？

普通 View 的 Java 层级不会直接变成 SurfaceFlinger 的多个 Layer。APP 先把 RenderNode / DisplayList 和 FrameInfo 交给 RenderThread，再由 Skia、GPU、BufferQueue 和 BLAST 把窗口像素、fence、frame number 与 SurfaceControl 事务交给 SurfaceFlinger。

源码快照：24bc82b5d阶段：UI → RT → GPU → BufferQueue → BLAST范围：普通硬件加速 View 窗口
01 / PIPELINE OVERVIEW

五段交接，每段处理的对象不同

ThreadedRenderer / DrawFrameTask
Skia / BufferQueue / BLAST

“APP 绘制完成”通常只表示 UI 线程已经录制或更新了本帧的 RenderNode / DisplayList。后面仍有跨线程同步、渲染树同步、GPU 提交、buffer 入队和 SurfaceFlinger 事务。

UI → RenderThread：交接的不是“已经画好的屏幕”

ThreadedRenderer.draw 先更新根 DisplayList，然后 syncAndDrawFrame 复制 FrameInfo 并把 DrawFrameTask 投递到 RenderThread。UI 线程等待 RT 返回 sync result，但这个等待不是 GPU fence。

APP 层输入View 个数、层级、动画 setter、invalidate 和 DisplayList 是否重录，会在这之前决定 RenderNode 树内容。输出RT 队列中的任务和同步结果。
关键边界：一个窗口里的普通 View 通常被 HWUI 画入同一个窗口 buffer；View 数量不等于 SurfaceFlinger Layer 数量。
02 / EVERY HANDOFF

每个阶段的输入、输出和事务

跨线程 / GPU / BufferQueue / Binder

UI → RT

输入：FrameInfo、RenderNode 树、DisplayList、暂存属性。
输出：DrawFrameTask 入 RT 队列；sync result 返回 UI。
事务：线程任务交接，不是 SurfaceControl 事务。

树同步

输入：staging 属性、DisplayList、FrameInfo。
输出：同步后的 RenderNode 状态、动画更新、damage、纹理准备。
事务：RT 内部状态变化和资源准备。

GPU / Skia

输入：RenderNode、damage、离屏层、Surface。
输出：GPU 命令、窗口目标 buffer、生产端写入依赖。
事务：GL swap 或 Vulkan finishFrame。

BufferQueue

输入：GraphicBuffer、acquire fence、damage、frame number。
输出：DEQUEUED → QUEUED，通知消费者。
事务：queueBuffer，不是逐 View 传输。

BLAST

输入：onFrameAvailable、BufferItem、SurfaceControl。
输出：ACQUIRED buffer、setBuffer 事务、FrameTimeline 信息。
事务：one-way Transaction.apply 进入 SF 队列。

BLAST ACQUIRED ≠ SF latch ≠ display present：BLAST 拿到 buffer 只代表客户端消费者已经取得 BufferItem。

05 / GPU AND BUFFER DETAILS

GPU 工作与 buffer 事务的实际分界

SkiaOpenGLPipeline / SkiaVulkanPipeline
Surface / BufferQueueProducer

Damage 与 buffer age

CanvasContext.draw 结合新旧 damage 和 buffer age 决定需要重画的区域。空 damage 在允许跳帧的条件下可能直接返回；damage 小不代表 UI 树访问成本为零。

GL / Vulkan 提交

GL 走 FlushAndSubmit，Vulkan 走 finishFrame。CPU 提交结束和 GPU 完成是两个事件；生产端 fence 是消费者读取前的依赖，不是显示器 present fence。

BufferQueue 入队

Surface 转交 BufferQueueProducer，记录 GraphicBuffer、slot、frame number、damage 和 fence。队列接收的是 buffer 引用与同步关系，不是 View、图片或绘制命令。

08 / BOUNDARIES

最后不要把这些状态混在一起

APP 绘制完成

UI 线程完成 DisplayList / RenderNode 录制或属性更新。

GPU 提交完成

RT/Skia 已提交 GPU 工作，buffer 带有生产端同步依赖。

BLAST 事务完成

客户端已 acquire buffer 并将 SurfaceControl.Transaction 送入 SF 队列。

仍未证明：SF 已经 commit/latch、HWC 已经 present、present fence 已 signal，或面板某一行已经发光。
