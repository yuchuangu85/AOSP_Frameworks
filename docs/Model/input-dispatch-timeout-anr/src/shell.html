REGISTER / 登记

服务端已发送，不等于客户端已读

InputChannel 传输与应用 Looper 执行是不同边界。主线程正在跑其他任务、被锁阻塞，或等待同步调用时，事件可以已经进入服务端 waitQueue，而应用回调还没开始。

FINISH / 完成

finish 是完成协议，不是下一帧上屏

finishInputEvent 交回 sequence 与 handled，经 native 发送 FINISHED。服务端匹配 seq 清理该条记录。渲染完成、业务消费成功与输入完成确认，不是同一个条件。

模型与证据范围

源码快照 {{REVISION}}。单窗口连接、1 至 3 个非批量化 MotionEvent、成功发布、固定示意调度；不模拟 key fallback、批量合并、完整多窗口触摸、完整策略弹窗与进程退出。普通窗口应用接收器通常绑定主线程；自定义 receiver 可以绑定其他 Looper。生成的取消事件仅标注，未逐条加入示意队列，恢复阶段假设它们没有额外过期项。

finish → ACK 清理的时段合并展示 native 输出、通道响应与服务端 command 清理的间隔，不声称该间隔通常很长。deadline 处画检测点、policy 的视觉转场延迟均不是调度实时保证。基础默认 5 s 仍受 HW multiplier 与窗口配置影响。
