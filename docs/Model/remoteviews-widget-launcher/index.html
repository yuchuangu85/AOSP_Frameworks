当前仓库与 Launcher 的边界

本页依据当前仓库快照 24bc82b5d25d 的 RemoteViews、AppWidget 服务、框架 Host 与常规 View 绘制链。仓库不含 Launcher3 的 Workspace、LauncherAppWidgetHost 等具体实现，因此右侧为 Launcher“宿主角色”示意，不声称验证其私有方法、线程配置或桌面网格摆放策略。

场景假设绑定已授权、widget/provider/host 有效、URI 权限与内存检查通过、没有多用户锁定或遮罩。首次模型选择容器先准备、更新随后到达的可行顺序，不把它当所有设备上的唯一顺序。局部更新明确已有全量缓存。同步/异步、复用/重建、错误回退均按所选分支演示。

所有时间与最终“示意画面更新”均为教学假设，无真机截图、FrameTimeline、present fence 或物理显示测量。集合小组件、legacy list deferred-update、DrawInstructions、复杂尺寸变体、并发取消与 PendingIntent 启动策略未完整模拟。

只有大于 lastWidgetUpdateSequenceNo 的条目才作为未发送更新补发。视图条目读取当前有效描述；结合服务端按 ID_VIEWS_UPDATE 覆盖序号的实现，断线期间多次更新并不是每个中间版本都重放。setListener 还可主动拉取当前描述，但本机制不是等待 Host 渲染 ACK 后再确认的可靠显示协议。

Host 挂载后进入普通 View 绘制链，完成回调不是上屏回执onViewApplied / 6 段

本仓库未包含 Launcher3，只能确认框架 AppWidgetHostView 与普通 View/ViewRootImpl 路径，不能补造 Launcher 自身的布局、可见性或线程策略。异步 listener 的 onViewApplied 调用 applyContent；新建内容经 addView 加入 Host，已有内容 reapply 时可以不重新添加。若 Host 已连接到可见窗口，布局/失效请求会按普通 View 层级到达 ViewRootImpl 并安排后续 traversal，条件满足才绘制。尚未 attach、不可见、取消 draw 等都会改变这条路径；这里不测量或宣称精确屏幕显示时刻。

base/core/java/android/appwidget/AppWidgetHostView.javaL719-727

这是框架 Host 接住异步结果的 listener：进入 onViewApplied 时甚至还要调用 applyContent 来挂载新内容。回调名称本身不保证 View 已加入某个已 attach 的 Launcher 窗口，更不是屏幕呈现回调。

        mColorMappingChanged = false;
// ...
        if (!recycled) {

            addView(content);

                    Choreographer.CALLBACK_TRAVERSAL, mTraversalCallback);

            pokeDrawLockIfNeeded();

            removeTraversalBarrier();
            performTraversals(frameTimeNanos);
        }
    }

点击描述在 Host 化为本地监听器，经 PendingIntent 发起交互setOnClickPendingIntent / 3 段

普通非集合子项的点击路径中，应用调用 setOnClickPendingIntent 只追加携带 RemoteResponse/PendingIntent 的动作描述。Host 回放动作后，在自己的目标 View 上安装本地 setOnClickListener；用户点击才由 RemoteResponse 交给 InteractionHandler，框架默认处理最终通过 PendingIntent 的 IntentSender 发起交互。跨进程不传输这个监听器 lambda 或 View 实例，也不是直接回调应用里的某个 Java 闭包。本组不展开集合点击、Launcher3 自定义处理或目标组件的后续执行。
