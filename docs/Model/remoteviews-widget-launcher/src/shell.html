IDENTITY / 身份

Provider、Widget 实例、Host 各有角色

Provider 定义小组件与更新逻辑；appWidgetId 识别一个已绑定实例；Host 持有对应的 AppWidgetHostView。同一个 Provider 可有多个实例，RemoteViews 本身不决定桌面网格位置。

INTERACTION / 反向交互

点击不是把桌面的 View 回传给应用

提供方可写入 PendingIntent 响应；宿主应用 Action 后建立本地点击处理，再由允许的交互路径触发 PendingIntent。不是序列化普通 OnClickListener 或把本地 View 对象送回 Provider。

04 / SOURCE EVIDENCE

模型依据与明确未覆盖的边界

当前仓库与 Launcher 的边界

本页依据当前仓库快照 {{REVISION}} 的 RemoteViews、AppWidget 服务、框架 Host 与常规 View 绘制链。仓库不含 Launcher3 的 Workspace、LauncherAppWidgetHost 等具体实现，因此右侧为 Launcher“宿主角色”示意，不声称验证其私有方法、线程配置或桌面网格摆放策略。

场景假设绑定已授权、widget/provider/host 有效、URI 权限与内存检查通过、没有多用户锁定或遮罩。首次模型选择容器先准备、更新随后到达的可行顺序，不把它当所有设备上的唯一顺序。局部更新明确已有全量缓存。同步/异步、复用/重建、错误回退均按所选分支演示。

所有时间与最终“示意画面更新”均为教学假设，无真机截图、FrameTimeline、present fence 或物理显示测量。集合小组件、legacy list deferred-update、DrawInstructions、复杂尺寸变体、并发取消与 PendingIntent 启动策略未完整模拟。
