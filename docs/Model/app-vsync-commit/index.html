App VSYNC 后，COMMIT 到底做了什么？

COMMIT 是 Traversal 之后的应用侧收尾阶段。它不是 SurfaceFlinger 的事务提交，也不是“像素已经显示”；APP 还可以使用 ViewTreeObserver 的 frame commit callback 观察硬件渲染内容是否提交到 swap chain。

01 / FRAME ORDER

COMMIT 位于 Traversal 之后

Choreographer.java
L353–363 · L1208–1211

Choreographer 将 CALLBACK_COMMIT 定义为 post-draw operations for the frame。它在 Traversal 回调返回后执行；源码还说明，如果重布局导致跳帧，COMMIT 回调看到的 frame time 可能被更新为更接近“这些状态真正生效的帧”。

COMMIT：处理 Traversal 返回后的回调

doCallbacks(CALLBACK_COMMIT) 会从 COMMIT 回调队列提取已到期记录并执行。它可以用于 post-draw 的应用工作，但 COMMIT 本身不等待 GPU、BufferQueue、SurfaceFlinger 或面板。

当前证据Choreographer 注释：Handles post-draw operations for the frame。重要边界Choreographer COMMIT 和 ViewTreeObserver frame commit callback 不是同一个事件。
核心结论：COMMIT 表示应用侧 Traversal 后回调机会；“frame 已提交到 swap chain”需要另一个硬件渲染 frame commit callback。

Choreographer CALLBACK_COMMIT

应用 Looper 上的 callback 队列阶段。Traversal 完成后，Choreographer 提取已到期的 Runnable/FrameCallback 并执行。它是时间顺序边界，不是渲染提交结果。

Traversal return → doCallbacks(COMMIT)
Runnable → APP post-draw work

ViewTreeObserver frame commit callback

APP 通过 registerFrameCommitCallback 注册。硬件渲染器在当前渲染内容已提交到 swap chain 后触发；回调时 frame 可能还没有在显示器上可见。

registerFrameCommitCallback → capture
HardwareRenderer → setFrameCommitCallback

SurfaceFlinger / HWC commit

这是更下游的系统显示链语义。不能用 Choreographer COMMIT 或 APP frame commit callback 代替它，更不能由它们证明物理面板发光。

05 / FRAME COMMIT API

ViewTreeObserver 的 frame commit callback 观察什么

ViewTreeObserver.java
L760–780 · ViewRootImpl.java L5874–5901

注册

APP 调用 registerFrameCommitCallback。ViewRootImpl 在硬件渲染启用时 capture 这些 callback，并交给 HardwareRenderer.setFrameCommitCallback。

触发条件

HardwareRenderer 报告当前渲染内容已经渲染并提交到 swap chain。回调并不保证当前内容已经在显示器上可见。

适合用途

源码文档特别提到可以和 PixelCopy 配合，用于更可靠地捕获当前已经提交的 UI 内容。软件渲染路径下该 API 不生效。

不要把它当 present：frame commit callback 只证明应用渲染内容已经提交到 swap chain；它不证明 SurfaceFlinger 已 latch、HWC 已 present 或面板已发光。

Choreographer COMMIT

应用侧 post-draw 回调机会。它不保证硬件渲染已经提交。
