App VSYNC 后，TRAVERSAL 到底做了什么？

Traversal 是 APP 把前面阶段产生的状态变化变成 View 树工作的一段：它检查窗口和 Surface，决定是否 relayout，执行 measure、layout、PreDraw 和 draw，并把结果交给后续渲染。

01 / FRAME ORDER

TRAVERSAL 位于 Insets 之后、COMMIT 之前

Choreographer.java
L347–351 · L1204–1211

Choreographer 将 CALLBACK_TRAVERSAL 定义为处理 layout 和 draw 的阶段。它不是“每帧无条件全树重做”，而是 ViewRootImpl 根据 mLayoutRequested、dirty 区域、窗口状态和 PreDraw 结果选择分支。

TRAVERSAL：不是一个单独的 draw 调用

ViewRootImpl.doTraversal 进入 performTraversals。这个方法可能包含窗口 relayout、measure、layout、PreDraw、draw，以及因为布局期间再次 requestLayout 而触发的第二次布局。

当前证据CALLBACK_TRAVERSAL 的源码注释是 Handles layout and draw。边界没有布局请求时，稳定几何可能跳过 measure/layout；没有 dirty 或动画时也可能不绘制。
核心结论：Traversal 的产物是“本帧 View 树已经完成的几何和绘制准备”，不是 GPU 已完成，也不是屏幕已 present。
02 / TRAVERSAL PIPELINE

performTraversals 会按条件经过五个主要阶段

L3924–4944

1. 准备窗口

检查停止、可见性、Surface、配置、Insets、窗口尺寸和 mLayoutRequested。

2. relayoutWindow

必要时和 WindowManager 协商窗口 frame、Surface、Insets、可见性和同步信息。

3. measure

根 View 和 ViewGroup 根据 MeasureSpec 计算 measuredWidth / measuredHeight。

4. layout

ViewGroup 给子 View 设置边界；布局期间 requestLayout 可能触发第二次 pass。

5. PreDraw / draw

PreDraw 可取消本轮；通过后执行 draw、DisplayList 录制和 Surface 同步。

05 / APP EFFECTS

APP 可以怎样触发或改变 Traversal

View.java / ViewRootImpl.java
请求会被合并，不等于立即执行

requestLayout：几何变化

设置 PFLAG_FORCE_LAYOUT 和 PFLAG_INVALIDATED，并沿父链传播。最终 ViewRootImpl 设置 mLayoutRequested，下一次 traversal 可能执行 measure/layout。

invalidate：绘制变化

设置 DIRTY / INVALIDATED，并通过 invalidateChild 传播 dirty Rect。几何稳定时可以只走 draw，而不重新 measure/layout。

布局期间再次请求

自定义 onMeasure/onLayout 或子 View 在 layout 中 requestLayout 时，ViewRootImpl 会记录请求者；必要时执行第二次 pass，第二次仍请求的推迟到下一帧。

APP 操作选择：只改颜色、文本绘制或 RenderNode 属性，通常更接近 invalidate/draw；改尺寸、LayoutParams、父子关系或约束，通常需要 requestLayout/measure/layout。
06 / WINDOW AND PREDRAW

Traversal 还负责窗口协商和绘制前最后一道门

ViewRootImpl.java
L4205–4318 · L4824–4903

relayoutWindow

窗口尺寸、可见性、Insets、Surface 或 WindowManager 参数变化时，APP 通过 relayoutWindow 和系统协商最新窗口状态。relayout 不是 View 树的 layout，它是窗口边界/Surface 协商。

dispatchOnPreDraw

ViewTreeObserver 的 PreDraw listener 在 draw 前执行。任何 listener 返回 false 都可以取消本轮绘制，并让后续 traversal 重新安排。

performDraw

PreDraw 通过后，ViewRootImpl 触发 OnDraw，判断 dirty、mIsAnimating、无障碍焦点和 Surface 状态，再进入 ThreadedRenderer 或软件绘制。

08 / BOUNDARIES

Traversal 完成不等于 GPU 和屏幕完成

Traversal 完成

View 树已经完成本轮可执行的窗口协商、测量、布局、PreDraw 和绘制提交准备。

RenderThread / GPU

硬件渲染还要同步 RenderNode、取得 buffer、提交 Skia/GL/Vulkan 工作并等待 GPU 依赖。

显示完成

后续还要经过 BufferQueue、BLAST、SurfaceFlinger、HWC 和 present fence；源码不能直接证明面板某一行何时发光。
