## 工作流程

### 步骤 1：项目启动

**目标**: 明确 Android 应用目标、范围和约束

**活动**:
1. 理解 Android 应用类型和目标用户
2. 识别 Android 平台特定需求
3. 确定 Google Play 发布计划
4. 评估 Android 技术可行性

**输出**:
```markdown
## Android 项目启动清单

### 基本信息
- [ ] 应用名称
- [ ] 应用类型（工具/社交/游戏/电商等）
- [ ] 目标用户群体
- [ ] 核心功能需求
- [ ] 商业模式（免费/付费/内购/广告）
- [ ] 预期上线时间

### Android 平台规划
- [ ] 最低支持版本（API Level）
- [ ] 目标版本（API Level）
- [ ] 支持设备类型（手机/平板/折叠屏/穿戴设备）
- [ ] 支持屏幕尺寸
- [ ] 需要的权限
- [ ] 需要的硬件（相机/传感器/NFC等）

### 发布规划
- [ ] Google Play 开发者账号
- [ ] 发布渠道（Google Play/第三方市场/企业分发）
- [ ] 发布策略（灰度/全量）
```

**调用**: `android-project-initiation` Skill

### 步骤 2：需求分析阶段

**目标**: 完整理解并文档化 Android 应用业务需求

**活动**:
1. 收集和整理业务需求
2. 区分功能性需求和非功能性需求
3. 编写 Android 用户故事
4. 定义验收标准
5. 识别 Android 平台特殊需求

**输出**:
```markdown
## Android 需求分析阶段交付物

- [ ] 需求规格说明书 (SRS)
- [ ] 用户故事列表
- [ ] 产品待办列表 (Product Backlog)
- [ ] 验收标准文档
- [ ] 需求跟踪矩阵
```

**调用**: `android-requirements-analysis` Skill

### 步骤 3：架构设计阶段

**目标**: 设计 Android 应用整体架构和技术方案

**活动**:
1. 选择 Android 架构风格（MVVM + Clean Architecture）
2. 设计系统分层和模块划分
3. 选择技术栈（Kotlin、Compose、Hilt 等）
4. 应用 Android Jetpack 组件
5. 确保架构满足性能和可维护性要求

**输出**:
```markdown
## Android 架构设计阶段交付物

- [ ] 架构设计文档 (ADD)
- [ ] 技术选型报告
- [ ] 架构决策记录 (ADR)
- [ ] 架构图（逻辑/进程/物理视图）
- [ ] 模块依赖图
```

**调用**: `android-architecture-design` Skill

### 步骤 4：详细设计阶段

**目标**: 将架构设计细化为可实现的技术方案

**活动**:
1. 设计模块详细结构
2. 定义接口（API/内部接口）
3. 设计数据库结构
4. 绘制 UML 模型图
5. 定义算法和业务流程

**输出**:
```markdown
## Android 详细设计阶段交付物

- [ ] 详细设计文档 (DDD)
- [ ] API 接口文档
- [ ] 数据库设计文档
- [ ] UML 模型图
- [ ] 接口契约定义
```

**调用**: `android-detailed-design` Skill

### 步骤 5：编码实现阶段

**目标**: 根据设计文档实现 Android 应用功能

**活动**:
1. 使用 Kotlin 编写高质量代码
2. 实现 Jetpack Compose UI 组件
3. 实现 MVVM 架构和 Clean Architecture
4. 遵循 Android 编码规范和最佳实践
5. 确保代码质量和可维护性

**输出**:
```markdown

- [ ] 完整源代码
- [ ] 代码注释
```

## Android 项目开发向导

### 新项目启动向导

当用户说"开始 Android 项目"时，按以下流程执行：

```
1. 询问项目基本信息
   - 应用类型（工具/社交/游戏/电商等）
   - 目标用户群体
   - 核心功能需求
   - 技术栈偏好（Kotlin/Java, Compose/XML）
   - 团队规模
   - 时间约束

2. 调用 android-project-initiation Skill
   - 进行可行性分析
   - 制定项目计划

3. 创建 Android 项目脚手架
   - 初始化代码仓库
   - 创建目录结构
   - 配置 Gradle
   - 配置 AndroidManifest.xml

4. 进入下一阶段
   - 提示用户继续需求分析
```

## 最佳实践

1. **市场导向**: 基于市场需求而非技术驱动
2. **合规优先**: 严格遵守 Google Play 政策和隐私法规
3. **渐进发布**: MVP -> Alpha -> Beta -> 正式版本
4. **用户中心**: 关注用户体验和反馈
5. **持续迭代**: 快速响应用户需求
6. **数据驱动**: 使用 Firebase Analytics 等工具收集数据
7. **质量优先**: 代码质量、测试覆盖率、性能指标
8. **文档同步**: 代码和文档同步更新

## 常用命令速查

```bash
# Android 项目开发常用命令

# 项目初始化
git init
git flow init

# 创建 Android 项目
npx react-native init MyApp
# 或
flutter create my_app

# 构建 Debug APK
./gradlew assembleDebug

# 构建 Release APK
./gradlew assembleRelease

# 构建 Release AAB (Google Play 推荐)
./gradlew bundleRelease

# 运行单元测试
./gradlew testDebugUnitTest

# 运行集成测试
./gradlew connectedDebugAndroidTest

# 运行所有测试
./gradlew test

# 生成覆盖率报告
./gradlew jacocoTestReport

# 签名 APK
jarsigner -verbose -sigalg SHA1withRSA -digestalg SHA1 -keystore release.keystore app-release-unsigned.apk alias_name

# 安装 APK 到设备
adb install app-debug.apk

# 查看设备日志
adb logcat

# 清理构建
./gradlew clean
```
